ParSolGen

Write the algorithm as a sequential program over blocked arrays. ParSolGen produces the parallel MPI program.

Overview

A ParSolGen program has two parts:

  • An algorithm description (.sol file): a small C-like program that says what is computed on which pieces of data, and in which order. Data lives in distributed blocked arrays.
  • Kernels (ucodes.h): ordinary sequential C++ functions that do the actual computation on one or a few blocks at a time.

The sgc compiler analyses the description, derives the data dependencies between kernel calls, and emits C++ (out.cpp). Compiled with mpicxx and linked to the PSRts runtime library, it becomes an MPI program. The runtime distributes blocks across nodes and threads, balances the load, moves data between nodes and to GPUs, and runs kernels as soon as their inputs are ready.

This guide uses the 2D heat equation solver as its running example.

Program structure

A .sol file contains imports that declare the kernels, and one exported subroutine, which is the program entry point.

heat.sol
import print_iter(in int iter);
import print_time();
import time_start();
import _calc_main(in double a, in double dt, in double dx, in double dy,
                  in int prev_n1, in int prev_n2, in Array<double> prev[prev_n1][prev_n2],
                  in int curr_n1, in int curr_n2, out Array<double> curr[curr_n1][curr_n2]);

export sub main()
{
    int nb = 10;
    int mb = 10;
    double a = 100;
    double dx = 0.01;
    double dy = 0.01;
    double dx2 = dx * dx;
    double dy2 = dy * dy;
    double dt = dx2 * dy2 / (2.0 * a * (dx2 + dy2));
    // ...
}
  • import name(...) declares a kernel and its parameters. Each parameter is marked in (read) or out (written). This is what the dependency analysis relies on, so the direction must be correct.
  • export sub main() defines the entry point. The body uses familiar C syntax: int and double variables, arithmetic, for and while loops, and // comments.
  • Scalar statements such as double dt = …; run on every process. Work on array blocks happens only inside kernel calls.

Blocked arrays & versions

Distributed data is declared as a grid of blocks. The type in angle brackets gives the shape of a single block; the brackets after the name give the number of blocks:

int nb = 10;           // blocks along dimension 0
int mb = 10;           // blocks along dimension 1
int block_n_ = 100;    // interior cells per block, dimension 0
int block_m = 100;     // interior cells per block, dimension 1

// 10 x 10 grid of blocks; every block holds (100+2) x (100+2) doubles
// (the +2 is a one-cell ghost layer on each side)
Array<double[block_n_ + 2][block_m + 2]> A[nb][mb];

A block is addressed by its grid coordinates: A[i][j]. ParSolGen decides which node, and which device, owns each block.

Versions

Each block can have many versions, written as A{v}[i][j]. A version is written once and then only read. A new value of the same block goes into the next version. This single-assignment rule is how ParSolGen finds parallelism: a kernel that reads A{it} and writes A{it + 1} depends only on the kernels that produced the blocks it reads. Calls on different blocks are independent and run in parallel.

// one explicit time step: read version it, write version it + 1
_calc_main(a, dt, dx, dy,
    %block_n(A, 0), %block_n(A, 1), A{it}[i][j],
    %block_n(A, 0), %block_n(A, 1), A{it + 1}[i][j]);

A[i][j] without braces refers to version 0.

Shape macros

MacroValue
%block_n(A, d)Size of one block of A along dimension d (including ghost cells, here 102)
%n_blocks(A, d)Number of blocks of A along dimension d (here 10)
int _Update_SRC_block_n1_1 = %block_n(A,  0)-2;   // interior size: 100
int _Update_SRC_block_n2_1 = %block_n(A,  1)-2;
int _Update_SRC_n1_blocks_1 = %n_blocks(A,  0);    // 10
int _Update_SRC_n2_blocks_1 = %n_blocks(A,  1);

Kernels (user code)

Kernels are plain C++ functions in ucodes.h, next to the .sol file. The generated out.cpp includes it. Parameters map one to one, in order:

.sol parameterC++ parameter
in int nint n
in double adouble a
in Array<double> prev[n][m]const double* prev: one block, row-major, n*m values
out Array<double> curr[n][m]double* curr

A block's dimensions are passed as preceding int parameters, so the kernel knows its size. Here is the heat-equation step: the import, and its implementation:

heat.sol
import _calc_main(in double a, in double dt, in double dx, in double dy,
    in int prev_n1, in int prev_n2, in Array<double> prev[prev_n1][prev_n2],
    in int curr_n1, in int curr_n2, out Array<double> curr[curr_n1][curr_n2]);
ucodes.h
void _calc_main(
	double a, double dt, double dx, double dy,
	int n, int m, const double* prev,
	int in_n_unused, int in_m_unused, double* curr)
{
	const auto in_n = n - 2;   // interior size (block minus ghost layer)
	const auto in_m = m - 2;
	const auto dx2 = dx * dx;
	const auto dy2 = dy * dy;

	// copy the ghost frame unchanged
	for (std::size_t i = 0; i < m; ++i) {
		curr[i] = prev[i];
		curr[(n - 1) * m + i] = prev[(n - 1) * m + i];
	}
	for (std::size_t i = 0; i < n; ++i) {
		curr[i * m] = prev[i * m];
		curr[i * m + m - 1] = prev[i * m + m - 1];
	}
	// 5-point stencil on the interior
	for (int i = 1; i <= in_n; i++) {
		for (int j = 1; j <= in_m; j++) {
			int ind = i * m + j;
			int ip = (i + 1) * m + j;
			int im = (i - 1) * m + j;
			int jp = i * m + j + 1;
			int jm = i * m + j - 1;
			curr[ind] = prev[ind] + a * dt *
				((prev[ip] - 2.0 * prev[ind] + prev[im]) / dx2 +
				 (prev[jp] - 2.0 * prev[ind] + prev[jm]) / dy2);
		}
	}
}

Kernels can also take scalars only, for example progress output and timing:

ucodes.h
void print_iter(int iter)
{
	if (iter % 100 == 0)
	{
		std::cout << "IT: " << iter << "\n";
	}
}

void time_start()
{
	total_exec_time = MPI_Wtime();
}
Rule: kernels must only touch data passed to them. They must not keep pointers to blocks between calls, and must not write to in parameters. The runtime may run them on any node and thread.

Ghost-cell exchange

Stencil codes need neighbour values at block borders. Each block of the heat example has a one-cell ghost frame. After every step, the borders are copied between neighbouring blocks in two phases, using helpers from the runtime library (_read_ghost_double and _write_ghost_double, declared in CgGate/rts.h; float and 3D variants also exist).

1. Read edges. Each block packs its four interior edges (left, right, up, down) into a small edge array:

int ghost_edge_len = block_n_ * 2 + block_m * 2;
Array<double[ghost_edge_len][1]> ghost_edges[nb][mb];

for (int i = 0; i < nb; i++)
    for (int j = 0; j < mb; ++j)
        _read_ghost_double(block_n_, block_m, ghost_edge_len,
                           A{it+1}[i][j], ghost_edges{0}[i][j]);

2. Write ghosts. Each block's next version is built from its current version and the edges of its left, right, upper and lower neighbours. For interior blocks:

for (int i = 1; i < nb - 1; i++)
{
    for (int j = 1; j < mb -1; j++)
    {
        _write_ghost_double(
            _Update_SRC_block_n1_1,
            _Update_SRC_block_n2_1,
            ghost_edge_len,
            ghost_edges[i][j-1],      // left neighbour
            ghost_edges[i][j+1],      // right neighbour
            ghost_edges[i - 1][j],    // upper neighbour
            ghost_edges[i + 1][j],    // lower neighbour
            A{it + 1}[i][j],
            A{it + 2}[i][j]);
    }
}

Corner and edge blocks have no neighbour on one or two sides. They pass their own edges in those positions instead. The complete listing covers all nine cases. One full iteration therefore advances the version by two: it → it + 1 (stencil) → it + 2 (ghost update).

Tip: PySol generates this exchange for you with a single pysol_update_array call.

Build & run

1. Generate C++ from the algorithm description. The output is out.cpp by default; use -o to choose another name.

<parsolgen>/bin/sgc heat.sol

2. Compile with any MPI C++ compiler and link the runtime:

CPU
mpicxx -std=c++17 -O3 out.cpp \
    -I<parsolgen>/include -L<parsolgen>/lib \
    -lPSRts -l<blas_lapack> -lGKlib -fopenmp
CPU + GPU (Goopax release)
mpicxx -std=c++17 -O3 out.cpp \
    -DSG_USE_ACCEL=1 -DSG_USE_GOOPAX=1 -DPSTL_USE_PARALLEL_POLICIES=0 \
    -I<parsolgen>/include -I<goopax>/include/goopax-6.0-I<mkl>/include \
    -L<parsolgen>/lib -L<goopax>/lib64 -L<mkl>/lib/intel64 \
    -lPSRts -lmkl_intel_lp64 -lmkl_sequential -lmkl_core -lGKlib -fopenmp -lgoopax -ltbb

For GPU builds, ucodes.h can provide Goopax versions of kernels (for example calc_main_goopax, which takes a goopax::goopax_device and goopax::buffer<double> arguments). The runtime moves data between host and device.

3. Run with mpirun. OMP_NUM_THREADS sets the number of worker threads per process:

OMP_NUM_THREADS=16 mpirun -n 4 ./a.out

The heat example prints IT: … every 100 iterations and the total time. It then writes each block to a binary file of_<i>_<j> (two ints for the block size, followed by the interior values) for post-processing.

Example: heat equation

PySol

Write ParSolGen algorithms in Python. Compile and run them from the same script.

Overview

PySol is a Python front-end for ParSolGen. You write the algorithm as a Python function and decorate it with @pysol. The function is never executed as Python. Instead, at import time PySol reads its source, checks that it uses only supported constructs, and generates an equivalent .sol file. pysol_compile then runs sgc and the C++ compiler to build a shared library, and pysol_run loads it and calls the function.

@pysolsolver.py
→
generatedsolver.sol
→
pysol_compilesolver.so
→
pysol_runparallel run

Kernels are still written in C++ in ucodes.h, exactly as in ParSolGen.

Installation & config

PySol requires Python 3.8 or newer and an installed ParSolGen. Install it from the source directory:

cd pysol
pip install .            # or: pip install -e ".[dev]" for development (adds pytest)

PySol reads the compiler location and options from a JSON config file, normally config.json next to your script:

config.json
{
    "sgc": "/opt/parsolgen/bin/sgc",
    "compiler": "mpicxx",
    "compile_options": "-std=c++23 -DPSTL_USE_PARALLEL_POLICIES=0 -I/opt/parsolgen/include -L/opt/parsolgen/lib -lPSRts -lGKlib -fopenmp"
}

Quick start: heat equation

This is the ParSolGen heat solver written with PySol. Compare its length with heat.sol: the whole ghost-cell exchange becomes one call to pysol_update_array.

heat.py
from pysol import (Array, KernelArgument, Type, import_kernel, load_config,
                   pysol, pysol_compile, pysol_run, pysol_update_array)


@pysol
def solver():
    init_el_k = import_kernel("init_el",
                              [KernelArgument("ii", True, Type.Int),
                               KernelArgument("jj", True, Type.Int),
                               KernelArgument("n", True, Type.Int),
                               KernelArgument("m", True, Type.Int),
                               KernelArgument("A", False, Type.Double, 2)])
    print_el_k = import_kernel("print_el",
                               [KernelArgument("ii", True, Type.Int),
                               KernelArgument("jj", True, Type.Int),
                               KernelArgument("A", False, Type.Double, 2)])
    calc_main_k = import_kernel("calc_main",
                                [KernelArgument("a", True, Type.Double),
                                 KernelArgument("dt", True, Type.Double),
                                 KernelArgument("dx", True, Type.Double),
                                 KernelArgument("dy", True, Type.Double),
                                 KernelArgument("prev", True, Type.Double, 2),
                                 KernelArgument("curr", False, Type.Double, 2)])
    print_it_k = import_kernel("print_iter", [KernelArgument("it", True, Type.Int)])

    nb : Type.Int = 10
    mb : Type.Int = 10
    block_n_ : Type.Int = 100
    block_m_ : Type.Int = 100

    a : Type.Double = 100
    dx : Type.Double = 0.01
    dy : Type.Double = 0.01
    dx2 : Type.Double = dx * dx
    dy2 : Type.Double = dy * dy
    dt : Type.Double = dx2 * dy2 / (2.0 * a * (dx2 + dy2))

    A = Array(2, 2, [nb, nb], [block_n_ + 2, block_m_ + 2], Type.Double)
    for i in range(nb):
        for j in range(mb):
            init_el_k(i, j, nb, mb, A[i][j])

    it : Type.Int = 0
    while it < 10000:
        print_it_k(it)
        for i in range(nb):
            for j in range(mb):
                calc_main_k(a, dt, dx, dy, A[it, i][j], A[it + 1, i][j])
        pysol_update_array(A, it + 1, A, it + 2)
        it = it + 2
    for i in range(nb):
        for j in range(mb):
            print_el_k(i, j, A[it, i][j])


if __name__ == "__main__":
    load_config("config.json")
    pysol_compile("solver")
    pysol_run("solver")

Types & variables

Every scalar variable needs a PySol type annotation the first time it is assigned:

n  : Type.Int    = 10
vb : Type.Float  = n + 1
dt : Type.Double = dx2 * dy2 / (2.0 * a * (dx2 + dy2))
it = it + 2                  # later assignments need no annotation

Note: the decorator analyses only the function's own source. Values such as block counts must be literals or variables defined inside the decorated function. Module-level constants are not visible to it.

Importing kernels

import_kernel(name, args) declares a C++ kernel from ucodes.h and returns a callable to use inside the @pysol function. Each argument is described by KernelArgument(name, is_input, type, n_dims=0):

  • is_input: True for an input (in), False for an output (out).
  • n_dims: 0 for a scalar, N for an N-dimensional array block.
init_el_k = import_kernel("init_el",
                          [KernelArgument("ii", True, Type.Int),
                           KernelArgument("jj", True, Type.Int),
                           KernelArgument("n", True, Type.Int),
                           KernelArgument("m", True, Type.Int),
                           KernelArgument("A", False, Type.Double, 2)])   # 2D output block
hello_world_k = import_kernel("hello_world_k", [])                        # no arguments

In C++, each array argument becomes its block dimensions (ints) followed by a pointer, the same as in ParSolGen:

ucodes.h
//            ii      jj      n=nb    m=mb    A: dims then data
void init_el(int ii, int jj, int nb, int mb, int n, int m, double* a);

void calc_main(double a, double dt, double dx, double dy,
               int n, int m, const double* prev,       // input block
               int in_n_unused, int in_m_unused, double* curr);   // output block

void hello_world_k()
{
    int rank = 0;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    std::cout << "Hello world from pysol from " << rank << "!\n";
}

Calling a function that was not imported with import_kernel raises NotImportedKernel.

Arrays

Array(n_dims, n_block_dims, array_size, block_size, type, is_single_version=False) declares a blocked, versioned array: a grid of array_size blocks, each of shape block_size.

# 1D: 10 blocks of 20 floats
A = Array(1, 1, [n], [20], Type.Float)

# 2D: 10x10 blocks of 102x102 doubles (100x100 + ghost layer)
A = Array(2, 2, [nb, mb], [block_n_ + 2, block_m_ + 2], Type.Double)

# 3D: 10x10x10 blocks of 10x10x10 doubles
A = Array(3, 3, [nb, mb, lb], [block_n_, block_m_, block_l_], Type.Double)

# keep only the latest version of each block (SingleVersionArray in .sol)
x = Array(1, 1, [nb], [blockn], Type.Double, True)

Indexing and versions

The version comes first inside the first subscript; block coordinates follow:

PySolGenerated .solMeaning

A[it, i][j]A{it}[i][j]block (i, j), version it
A[it + 1, i][j][k]A{it + 1}[i][j][k]3D block, version it + 1
Zr[LATEST_VERSION, i]Zr{%latest}[i]most recently written version
x[it,]x{it}whole vector at version it (note the trailing comma)

Array operations

Halo (ghost-cell) exchange

pysol_update_array(src, src_version, dst, dst_version) fills the ghost layer of every block of dst_version from the neighbouring blocks of src_version. Blocks must include the one-cell ghost layer (block + 2). It works for 2D and 3D arrays.

it : Type.Int = 0
while it < 100:
    for i in range(nb):
        for j in range(mb):
            modify_k(i, j, A[it, i][j], A[it + 1, i][j])
    pysol_update_array(A, it + 1, A, it + 2)
    it = it + 2

pysol_update_array_3d_26_full_sum is a 3D variant for particle-in-cell codes. Blocks overlap their 26 neighbours by a two-cell slab, and the overlapping contributions are summed rather than copied.

Reductions

sum_value : Type.Double = sum(A)
max_value : Type.Double = max(A)
min_value : Type.Double = min(A)

Vector arithmetic

Whole blocked vectors can be combined in a single expression. No per-block loop is needed. @ is the dot product:

C = A + B                                    # element-wise sum of all blocks
beta : Type.Double = Zr[0,] @ Rl[0,]         # dot product -> (Zr, Rl)
x[1,] = x[0,] + a_c * Pr[0,]                 # axpy
reset(Zr)                                    # clear an array -> Zr = {};

Structs & GrowingArray

@pysol_struct declares a record type, used like @dataclass. Fields must be Type.Int, Type.Float or Type.Double. GrowingArray(n_dims, array_size, type) is a versioned array whose cells hold single values, including structs. It suits variable-size data such as particle mailboxes.

@pysol_struct
class Sample:
    a: Type.Int
    b: Type.Float
    c: Type.Double


@pysol
def growing_array_struct_test():
    init_k = import_kernel("init_struct_cell3d",
                            [KernelArgument("ii", True, Type.Int),
                             KernelArgument("jj", True, Type.Int),
                             KernelArgument("kk", True, Type.Int),
                             KernelArgument("s", False, Sample)])

    nb : Type.Int = 4
    mb : Type.Int = 4
    lb : Type.Int = 4

    A = GrowingArray(3, [nb, mb, lb], Sample)

    for i in range(nb):
        for j in range(mb):
            for k in range(lb):
                init_k(i, j, k, A[i][j][k])

Sparse matrices

CSRMatrix(size, n_blocks, nnz, ia, ja, a, type) wraps a CSR matrix split into a 2D grid of CSR sub-blocks. Kernels receive single blocks as Type.CSRBlock(Type.Double), and empty blocks can be skipped with is_zero. From the BiCG example:

csr_mv_k = import_kernel("csr_mv",
                         [KernelArgument("nb", True, Type.Int),
                          KernelArgument("blockn", True, Type.Int),
                          KernelArgument("block", True, Type.CSRBlock(Type.Double)),
                          KernelArgument("x", True, Type.Double, 1),
                          KernelArgument("ysrc", True, Type.Double, 1),
                          KernelArgument("ydst", False, Type.Double, 1)])

for i in range(nb):
    v = 0
    for j in range(nb):
        if not is_zero(A[i][j]):
            csr_mv_k(nb, blockn, A[i][j], Pr[0, j], Zr[v, i], Zr[v + 1, i])
            v = v + 1
